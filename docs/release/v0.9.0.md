# mod-events v0.9.0 — The 1.0 Release Candidate

**Release-candidate-style minor for `1.0`. Re-engineered the dispatcher around three goals: panic safety on every path, zero-allocation success path, and runtime-agnostic async. Verified with a property-test suite, an expanded cross-platform CI matrix (Linux x86_64 + ARM64 + musl, macOS ARM64, Windows x86_64), nightly AddressSanitizer, and `loom` model checking of the only non-trivial concurrency pattern in the crate.**

This is the API freeze. `0.9.x` patches will fix bugs found through community use. `1.0.0` follows once the public surface has had time to settle.

## What is mod-events?

A high-performance, type-safe, runtime-agnostic event dispatcher
library for Rust. Implements the observer pattern with priority +
middleware on top of a lock-free metrics path. Works with any async
executor (tokio, async-std, smol, embassy, …) — no runtime
dependency.

## What's new in 0.9.0

### Panic safety, both paths

`dispatch` and `emit` already wrapped each listener call in
`std::panic::catch_unwind` (added in 0.2.x post-release work).
`0.9.0` extends the same guarantee to `dispatch_async` via
`futures_util::future::FutureExt::catch_unwind`. A panicking
listener — sync or async — becomes a `ListenerError` in
`DispatchResult::errors()` with the message prefix
`"listener panicked: "`. Subsequent listeners still run; the
dispatcher remains usable for subsequent events.

### Zero-allocation success path

`DispatchResult` no longer pre-allocates a `Vec` for per-listener
results. The internal storage is a `Vec<ListenerError>` that stays
empty (and unallocated — `Vec::new()` does not allocate) on the
success path. A fully successful dispatch of N listeners now performs
**zero heap allocations** for the result. Failing dispatches allocate
proportional to the failure count, not the listener count.

`emit` skips the result-building path entirely. Same panic-safety
contract; no result vector to allocate-and-discard.

### Runtime-agnostic async

`mod-events` no longer depends on `tokio`. The `async` cargo feature
pulls in only `futures-util` for `catch_unwind`. The library uses
only `std::future::Future` and `std::pin::Pin`, so it works with any
executor. Examples and tests use tokio for convenience, but that is
a dev-dependency and is not propagated to consumers.

### Property-based testing

New [`tests/property_tests.rs`](https://github.com/jamesgober/mod-events/blob/0.9.0/tests/property_tests.rs)
covers six invariants over randomised inputs (~256 cases per
property per CI run):

- Dispatch invokes every listener exactly once.
- Dispatch respects priority then FIFO within equal priority.
- Subscribe + unsubscribe count invariant.
- Dispatch-count metric matches call count.
- Middleware blocks iff any middleware returns false.
- Clear drops every listener.

### Cross-platform CI proof

The CI matrix expanded from 3 to 5 host/target combinations:

- `ubuntu-latest` x86_64-unknown-linux-gnu
- `ubuntu-24.04-arm` aarch64-unknown-linux-gnu
- `ubuntu-latest` x86_64-unknown-linux-musl
- `macos-latest` aarch64-apple-darwin
- `windows-latest` x86_64-pc-windows-msvc

Every combination runs `fmt + clippy + build + test + doc`. Platform
divergence cannot land without being caught.

### AddressSanitizer in CI

New `asan` job runs the integration + property test suites under
`-Z sanitizer=address` on Linux nightly per REPS §Memory Debugging.
The crate has no `unsafe` of its own; ASAN exercises `parking_lot`
and `futures-util` internals through our test paths.

### Criterion in CI

New `bench` job runs `cargo bench --features async --bench dispatch_benchmark`
on Linux and uploads the report as a build artifact (30-day
retention). Persistent baseline tracking + 5%-regression-gate is the
next iteration.

### `EventDispatcher::clear_middleware()`

Drops every registered middleware function. Counterpart to `clear()`
(listeners only). Useful in test setup/teardown.

## Breaking changes

Two changes need attention if your code touches them. Most upgrades
require zero code change.

1. **`tokio` is no longer a transitive dep.** If your project was
   relying on `mod-events` to pull tokio into your tree, add tokio
   explicitly:
   ```toml
   [dependencies]
   mod-events = "0.9.0"
   tokio = { version = "1", features = ["..."] }
   ```
2. **`DispatchResult::errors()` returns `&[ListenerError]`** instead
   of `Vec<&ListenerError>`. Iteration is unchanged. Callers that
   assigned the return into a `Vec<&_>` need to switch to
   `&[ListenerError]` or call `.to_vec()`.

Plus a behavioral addition: a panicking async listener no longer
crashes the dispatching task — it becomes a `ListenerError`. This
matches the sync path. Code that relied on the panic propagating
should rework to inspect `DispatchResult::errors()`.

See [`docs/migration.md`](https://github.com/jamesgober/mod-events/blob/0.9.0/docs/migration.md#upgrading-from-mod-events-02x-to-090)
for the full upgrade guide.

## Performance

Numbers measured against `mod-events 0.9.0` on Windows x86_64
(integration-test bench, release profile):

| Scenario | Per-event latency | Throughput |
|----------|-------------------|------------|
| `emit` with 1 listener  | ~133 ns | ~7.5 M events/sec |
| `emit` with 10 listeners | ~244 ns | ~4.1 M events/sec |

Authoritative criterion baselines now run on Linux in CI and ship
as build artifacts. See [`docs/performance.md`](https://github.com/jamesgober/mod-events/blob/0.9.0/docs/performance.md).

## Stability promise

`0.9.0` is the API freeze. The shape of `EventDispatcher`, `Event`,
`EventListener`, `AsyncEventListener`, `Priority`, `ListenerId`,
`DispatchResult`, `EventMetadata`, `MiddlewareManager`, `ListenerError`,
and `AsyncEventResult` is committed. Behavioral contracts of every
`pub fn` are committed. The `async` cargo feature stays on by
default. MSRV stays at Rust 1.81.

`0.9.x` patches will land bug fixes from community use; `1.0.0`
follows once the surface has had time to settle.

## Installation

```toml
[dependencies]
mod-events = "0.9.0"

# For async support (default)
mod-events = { version = "0.9.0", features = ["async"] }

# Sync-only build
mod-events = { version = "0.9.0", default-features = false }
```

MSRV: Rust 1.81.
