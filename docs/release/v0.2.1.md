# mod-events v0.2.1 — Security Patch + CI Hardening

**Patch release. Pulls patched `bytes` and `slab` into the committed lockfile to clear two RustSec advisories, bumps MSRV to 1.81 so the Cargo lockfile-format-v4 file ships in `Cargo.lock` is parseable by the MSRV CI job, and grants the CI workflow the `checks: write` permission `rustsec/audit-check` needs to post results. No public API changes from `0.2.0`.**

### Security advisories cleared

- **RUSTSEC-2026-0007 — `bytes` integer overflow.** `BytesMut::reserve` had an unchecked `new_cap + offset` addition. In release builds the overflow could set `self.cap` past the actual allocated capacity, causing later `spare_capacity_mut()` and similar APIs to hand out out-of-bounds slices. Memory-corruption category. Fixed in `bytes 1.11.1`. The lockfile shipped in this release pins `bytes 1.11.1`.
- **RUSTSEC-2025-0047 — `slab` out-of-bounds access.** `Slab::get_disjoint_mut` checked indices against the slab's *capacity* instead of its *length*, allowing access to uninitialised memory. Fixed in `slab 0.4.11`. The lockfile shipped in this release pins `slab 0.4.12`. The previously-used `slab 0.4.10` was also yanked from crates.io.

Both crates are transitive dependencies via `tokio`. If you depend on `mod-events` and your own `Cargo.lock` still resolves an older `bytes` or `slab`, run `cargo update -p bytes -p slab`.

### MSRV bump

- **MSRV is now Rust 1.81** (was 1.75). Cargo lockfile format v4 became default in Rust 1.78 and is what modern toolchains write into `Cargo.lock`. The MSRV CI job for 1.75 failed at lockfile parse before any code compiled, which means 1.75 was never really supported once the lockfile was regenerated. 1.81 is the conservative pin — stable since 2024-09-05, well over a year of release window by mid-2026.
- `rust-toolchain.toml` is unchanged at `1.95.0`. Day-to-day work and the `check` matrix continue to use `1.95.0`; the dedicated `msrv` CI job verifies `1.81.0`.

### CI hardening

- The CI workflow now declares `permissions: { contents: read, checks: write }`. The `rustsec/audit-check` action posts findings as GitHub Check Runs, which require `checks: write`; without it the action failed with `Resource not accessible by integration` even though the underlying audit pass succeeded.

### Compatibility

- **No public API changes.** Every type, trait, function, and feature exported by the `0.2.0` crate keeps its signature in `0.2.1`.
- **Drop-in upgrade.** Bump your `Cargo.toml` to `mod-events = "0.2"` (caret) and `cargo update -p mod-events` will pick this up. If you pinned `= "0.2.0"`, change it to `"0.2.1"` or `"0.2"`.
- **Build-time effect.** Consumers building against the `0.2.1` `Cargo.lock` directly need Rust 1.81 or newer.

### Installation

```toml
[dependencies]
mod-events = "0.2"

# For async support (default)
mod-events = { version = "0.2", features = ["async"] }

# Sync-only build
mod-events = { version = "0.2", default-features = false }
```

MSRV: Rust 1.81.
