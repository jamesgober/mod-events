# mod-events v1.2.0

A 1.x minor release with fixes from an independent review. No breaking change. MSRV stays at 1.81.

## Fixed

- **`dispatch_async` can run inside `tokio::spawn`.** The future it returned was not `Send`, because it held a `&dyn Any` across an await point. Awaiting it in a spawned task, an axum handler or any multi-threaded executor task failed to compile with E0277. The future is now `Send`.
- **Middleware panics are caught.** A panicking middleware used to unwind into the caller of `emit`, `dispatch` and `dispatch_async`, against the panic-safety contract. Each middleware call is now wrapped in `catch_unwind`. A panic blocks the event: no listener and no later middleware runs, and the dispatch methods that return a `DispatchResult` report one error starting with `"middleware panicked: "`.
- **Listener ids are unique across dispatchers.** `unsubscribe` with an id from another dispatcher used to remove an unrelated listener and return `true`. It now returns `false`.

## Added

- `EventDispatcher::dispatch_async_all` runs sync and async listeners together in one priority order (FIFO within equal priority, across both kinds). Its result counts both kinds.

The existing methods keep their behaviour:

| Method | Sync listeners (`on`, `subscribe`) | Async listeners (`subscribe_async`) |
|---|---|---|
| `emit`, `dispatch` | run | not run |
| `dispatch_async` | not run | awaited |
| `dispatch_async_all` | run | awaited |

## Deprecated

- `EventListener` and `AsyncEventListener`. No dispatcher method accepts them. Register a closure instead:

  ```rust
  let priority = notifier.priority();
  dispatcher.subscribe_with_priority(move |e: &UserRegistered| notifier.handle(e), priority);
  ```

  Both traits stay available for the whole 1.x line.

## Documentation

- Each dispatch method's docs, the README and the API reference say first which listeners it runs.
- `docs/STABILITY.md` covers middleware panics, the need for `panic = "unwind"`, and the lack of a recursion guard.
- `docs/performance.md` drops claims that did not hold (lock-free reads, zero allocations on the async path, the old 262 ns figures and comparison table) and notes that dispatching one event type from many threads does not scale linearly.

## Upgrading

Change the version to `1.2`. Code that implements `EventListener` or `AsyncEventListener` gets a deprecation warning; nothing else needs to change. A caller that relied on a middleware panic unwinding out of `dispatch` now gets a blocked result with one error instead.
